## 执行方式

- 单一写入者：所有实现子任务串行使用当前工程 `H:/Projects/Unities/BattleCity`，主代理在实现 agent 活跃期间不修改工程。
- Unity 的 Library、现场编辑器与未跟踪用户文件使复制 worktree 并不能直接复用编辑器，因此本轮不启用并行 worktree 写入。
- 每个编号为一个有边界的交付；实现后检查实际 diff 与测试证据，再发起下一编号。必要的只读审查可以独立进行，编辑器测试操作仍串行。
- BC-107 是命中特效生命周期单一能力切面，允许配套修改 session/controller 的接入及专项测试，不包含完整死亡、AI、HUD 或阶段二会话系统。
- 阶段二按地图、共享坦克、AI、波次、基地、生命、会话、HUD、测试与闭环验收分属独占的顺序交付；不将阶段二整体委派给一个 writer。每项以前项保存后的代码和验收记录为交接依据。
- 每项记录修改文件、实际执行的测试、通过/失败/未运行、限制和下一步。子代理报告本身不等于主代理最终验收。
- 不手写场景、Prefab 或 Sprite meta；通过编辑器 API 生成、绑定与保存资源。
- 需要人工确认的手感或画面质量明确列为待确认，不以自动测试冒充人工通过。M1 未通过不进入阶段二；遇到无法自动闭合的里程碑门禁向用户报告。
- 遇到 subagent 基础设施故障、编辑器无法连接、产品规则实质冲突或验收失败，先报告并保留当前改动；不静默更换执行协议。
