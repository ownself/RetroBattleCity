# 阶段 0：核心规则与待校准参数（BC-006）

> 本文是后续实现的项目规则，不是“已核实原版”的声明。阶段0不实现下述战斗行为。除素材尺寸和工程配置外，原版数值均未逐项验证。

## 输入、时间与更新顺序

| 项目 | 冻结的项目规则 / 初始值 | 核实状态 |
| --- | --- | --- |
| 移动 | WASD / 方向键，四方向连续移动，不斜走 | 首版设计 |
| 射击 | Space，按住可按冷却重复射击；暂停/恢复清空边沿输入，仍按住的键需释放再按 | BC-104已验证冷却、在场上限、暂停输入；原型数值待校准 |
| 暂停 | Escape；战斗状态切换暂停，恢复不补算暂停时长；结果页不响应战斗输入 | 首版设计 |
| 同时按方向 | 最新按下的物理键优先（W/上箭头等别名独立追踪）；松开后回退到仍按住的最新键；同一采样完全同时发生按固定 Up→Left→Down→Right 优先 | BC-100测试通过；按渲染帧采样，不声称区分同次采样内的硬件事件先后 |
| 逻辑步长 | 固定60Hz，1/60s；时间用整数tick计数，不依赖Time.time的计时回调 | 工程设计 |
| 长帧 | 每渲染帧最多推进8个逻辑tick，超额积压丢弃并记录DroppedTicks计数，不在恢复时突然大量补算 | BC-100测试通过 |
| 失焦 | 本地单人自动暂停并清空输入，重新聚焦后需手动恢复；资源冒烟时CLI临时允许后台推进 | 首版设计 |
| 显示插值 | 本批不插值，只对显示坐标四舍五入到px，不写回逻辑；履带仅实际移动时每8 tick切帧 | BC-102/103自动验证通过；人工手感留BC-108 |

同一tick顺序：
1. 采样/归一化输入（AI用本tick开始时的状态快照，顺序按稳定实体ID）；暂停指令先处理。
2. 控制决策、计时器推进、转向对齐和坦克移动（稳定实体ID顺序，禁止互相穿越）。
3. 武器请求/冷却与在场弹数限制、产生子弹。
4. 子弹扫掠，按最早命中距离收集事件；同距离按边界→地形→基地→坦克→子弹、再稳定实体ID打破平局。BC-105已实现敌对子弹相对运动扫掠，用户报告38个专项案例全部通过。全局跨子弹事件按tick时间比例排序（单弹等价于距离），相同时间按上述类型/稳定目标ID/子弹租约ID排序；更早已消费的子弹使后续相关候选失效，一对敌弹各消费一次，同阵营弹穿过。
5. 结算伤害、砖墙损坏、受击和死亡，一发子弹同tick最多消费一次；地图变化先修改唯一逻辑数据，再同步显示。BC-106已在Session同tick消费命中并修改4px砖掩码（用户专项验收通过）；同tick全部子弹先扫掠旧快照，下一tick才看见新缺口，多逻辑tick的渲染帧也逐tick结算。
6. 拾取/出生与波次（死亡先结算），占用出生点则等待，不吞计数。
7. 判胜负并发状态事件；显示/HUD读取结算后的状态。

## 空间与碰撞

- 逻辑单位px，地图半开边界 `[0,208)`；坦克初始矩形16×16、中心定位，碰撞半宽8。以后缩小盒体必须有通道回归证明。
- 坦克沿一个轴连续移动；转为垂直方向时，垂直于新运动轴的位置参照8px通道网格对齐。单次直接吸附最大距离2px；距离更大时，在完整对齐路径无阻挡的前提下按正常移动速度逐步接近最近对齐线，持续按侧向键即可完成转弯，不要求继续按原方向键。**只有对齐后的盒体和整个吸附路径无阻挡才可对齐**；真正被墙阻挡时不强行转向或穿墙。该补正针对侧向转弯永久拒绝问题，用户已人工复测反馈良好；补丁65项转向自动回归在BC-104批次全部通过，完整战斗回归仍留BC-108。
- 矩形边缘恰好接触不算穿透，进入阻挡区域才阻止；转换单元索引时以half-open与统一epsilon处理，禁止各脚本自定偏差。
- 子弹以扫掠矩形/线段扩张目标查询，不能只检查帧末位置。初始逻辑碰撞盒4×4，显示用8×8画布。BC-104已接入炮口中心为坦克中心沿实际朝向偏移10px（8+2），默认15tick冷却和最多1弹，结束后释放Owner计数；初次立即可发，下一次最早相隔15tick。被冷却/上限拒绝的短按不排队，按住可在条件满足后重发。BC-105已接入边界、砖钢墙及逻辑目标的连续扫掠，用户报告38项专项测试通过并确认砖/钢挡弹正常；BC-105验收时砖墙仅挡弹；后继BC-106已接入局部破坏，用户确认21项逻辑及22项显示专项通过。目标采用移动结算后的矩形快照，基地双方弹均命中，友军/自身坦克忽略；血量、真实敌人和基地实体不在本批实现。炮口已在墙中时t=0消费，单纯平行擦边或背离接触面不产生地形/目标命中；边界起点已接触则立即回收。每tick命中列表不可变记录保留原租约，下一tick清空，破墙现由Session同tick消费，后续伤害/特效也须同tick消费。
- BC-106原型破墙：沿入射轴只清命中4px格的一层，垂直轴16px条带下/左边缘按`floor((弹中心-8+epsilon)/4)*4`对齐；边缘裁剪不内移，只清仍存的砖。最后4px位清空才把8px格变Empty；普通弹不破钢。显示按revision读取当前掩码，保留原8px纹理/UV/PPU16并裁剪几何，不拉伸残片、不反写逻辑。专项曾暴露测试布局及EditMode不支持Sprite几何覆盖的问题，已修补并分为21项EditMode逻辑、22项PlayMode显示，用户确认两组全部通过；未冒称原版精确规则。
- 玩家/敌人共用组件，阵营控制来源分离；不启用动态刚体推动或TilemapCollider作为第二碰撞真相。

## 胜负与生命周期

- 同一步：**基地摧毁或玩家生命耗尽优先于敌军清零的胜利**。最后敌人和基地同时死亡→失败。
- 敌军清零条件：待生成序列耗尽、存活敌人数=0、无等待生成敌人；单纯场上暂时没有敌人不算胜利。
- 胜负只发布一次。暂停冻结战斗tick、护盾/道具/复活时间，不冻结展示或菜单自身的非战斗效果。
- 重开重建逻辑地图，清空实体/池内状态、事件订阅、在场弹计数、道具和计时器，恢复初始种子/波次/生命。
- 首版不实现：双人、手柄、完整升级/道具/冰面、网络、音频、完整原版关卡；它们仍按实施计划后续阶段执行。
