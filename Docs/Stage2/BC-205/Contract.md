## 产品与时间语义（未校准原型，不声称原版事实）

1. 初始**总共3条生命，包含当前**；每次真实活→死只扣1，多弹同tick不重复扣。初始出生不带保护；每次复活带120tick保护。生命耗尽锁存请求/一次事件供BC206消费，不冻结整局、不做胜负/重开/HUD。
2. 精确端点：死亡发生tick D的伤害阶段，生命扣减并建立剩余60tick等待，**D本身不扣等待**。后续每个战斗tick末等待减1，D+60首次允许复活；ready但占用保持0逐tick复查，不重复扣生命/重置倒计时。
3. 复活在伤害后出生阶段提交（**玩家复活先于敌波次出生**），本tick不倒流移动/开火/受伤。复活提交后保护剩余120；后续120个完整战斗tick的扫掠/伤害均受保护，在各tick伤害结算后减1。若R=D+60为复活tick，则R+1～R+120受保护，R+121首次可伤。已保护敌弹仍被扫掠消费，不只是穿透/过滤目标。
4. 暂停/失焦不推进等待/保护/盾动画，无恢复补算；新生盾动画仅从逻辑tick/保护剩余派生。生前普通移动/子弹/波次语义不变。
5. 生命模型与Unity对象/坦克/地图/子弹无耦合。可将结算后的玩家存活状态传给模型，由其识别每代一次死亡，并通过宿主成功复活回调决定提交；模型公开只读生命/等待/保护/耗尽状态。API由模型owner交接冻结，但上述端点不可自行改变。

## 兼容、复活原子性与残留处理

- Stage01通过Controller显式启用玩家生命周期；CombatArena及旧ArenaSession两/三/四参数用法默认不启用，保留死亡不复活的旧专项隔离。构造新增末尾可选生命参数（null默认禁用）；启用使用验证过/不可变且快照的3/60/120原型参数，避免新建不必要数据资产。
- 不替换PlayerTank、Player、PlayerWeapon引用或玩家稳定ID1：同一TankState/Motor/Weapon在复活时通过最小internal生命周期接缝重置，存活其他坦克的引用/稳定ID/命令/AI种子不变。玩家Spawn、初始HP及武器参数取会话创建时快照，不受运行时修改作者asset影响。
- 复活前完整16px查询地图残砖/钢/水边界、活坦克、基地（含废墟）和敌出生预留，沿用统一Map.CanOccupy/现有blockers。死亡玩家不占用原位置，不人为预留玩家出生点推开敌人；受阻则等，不挤开/穿墙/吞生命。只有原子成功才提交复活。
- 死亡玩家旧弹按BC201共享死亡规则继续完成，不在伤害循环中提早删除导致同tick漏伤害；**成功复活时**仅回收该玩家武器尚存旧弹并准确释放Owner lease，重置其冷却为0/在场数为0。不能清空全BulletWorld或敌军弹，不能直接把计数归零掩盖lease泄漏。最后一命死亡没有复活，旧弹保留正常结算，以便BC206处理同tick败优先。
- 复活恢复初始HP、出生位置、朝上、履带帧0、静止、空命令、武器就绪；生命不增加，不重建地图/敌波次/Clock/ID分配。复活当tick不发弹，后续首次新按可立即发。
- 死亡/等待期间不缓存输入；死亡及复活清除命令/FirePressed，并对一直按住或死时新按下的键执行现有SuppressHeld口径：释放再按后才生效，不能因多tick渲染帧意外发弹/移动。Esc暂停始终可用。
- 显示仅从逻辑状态投影：死亡隐藏玩家、成功复活显示原型坦克与`effect.shield.0/.1`；盾位置跟随玩家、排序合理、保护结束/死亡/禁用/销毁无残影，不使用Collider/Rigidbody/Time.time独立计时。Stage01作者recipe与当前场景启用一致，CombatArena保留旧隔离。
