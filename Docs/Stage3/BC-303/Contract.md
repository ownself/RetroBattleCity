# BC-303 道具生成与拾取框架契约

用户明确授权继续BC303；依赖BC301已由人工反馈验收。主代理直接实施，无委派/提交推送。保留BC300～302与既存.vsconfig，未授权BC304～309。

## 本项项目默认（全部待校准，非原版事实）

- Stage01显式绑定 `PickupDefinition`。成功自然生成序列的0-based索引3/10/17（第4/11/18敌）为携带者，兼容四种敌人；手工AddTank不自动获得资格，预备期不消耗资格。
- 携带者每8逻辑tick交替自身HP阶段Sprite和同型红色Sprite，仍读取朝向与履带帧；暂停冻结。不修改阵营/HP/材质/移动武器/随机AI。第一次有效敌对伤害（包括非致命和致命）消耗资格；保护/友军/重复命中不触发或重复掉落。装甲掉落后立即回归当前HP色阶。
- 同tick全部伤害和出生结算后才处理掉落。终局tick清空活动道具且不生成/拾取；若玩家死亡无活着的寻路起点，此次机会消费但不生成/重试，原道具保留。普通死亡不删除已活动道具，复活保护不妨碍活玩家拾取。
- 独立非零seed303的xorshift随机流：六等权类型Clock/Grenade/Helmet/Shovel/Star/Tank，然后选一个候选位置；不使用UnityEngine.Random、不影响波次/AI随机流。不启用素材中的gun道具。
- 最多一个活动道具。成功新掉落替换旧的并生成新ID；无候选不替换、不前进RNG，不暗中改放墙里、强制传送或无限重试。无自动过期/道具闪烁计时，本项不增加限时效果。
- 16×16道具占位、8px中心网格。逻辑Map.CanOccupy验证完整坦克足迹，不能落在砖残片/钢/水/基地/出界；从活玩家实际坐标经轴向安全连接到8px锚点，floodfill同一静态可达分量。基地永久挡路；活坦克和出生预留排除目的地，但不作为永久路径封锁。该算法保守，有路不保证找到锚点；无候选即有界拒绝，不在不可达房间随机放置。
- 只按活玩家结算后AABB严格重叠拾取（边缘相触不算），不由Collider/Trigger/显示触发。先清活动槽，再增加计数并发布不可变类型/ID/位置/tick收据，重复Step/Render不再结算。敌人不能拾取。
- 本项仅生成、显示和一次性收据账本，**不升级、不加盾、不加命、不冻结、不爆炸、不强化墙，也不增加分数**。具体效果由BC304～306接入，奖励分数留BC308；不得让没有实现的图标被描述为已生效。
- 旧场景/构造默认opt-out。Stage01仅新增pickupDefinition单字段绑定；完整重建recipe同步。资产只通过Editor API创建，Prepare不覆盖已有调参。
- 会话深快照配置，重开新会话归零计数/随机流/资格/活动槽；退休旧会话清槽，禁用仅暂停并隐藏，重新启用controller显式重绑；销毁释放显示和私有快照。
